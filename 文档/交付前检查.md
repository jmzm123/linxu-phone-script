# 交付前检查

初稿写完后逐项过一遍，不打分。每一项要么通过，要么改掉，改不了的写进给林序的报告。

---

## 1. 技术对不对

- 稿子里每一个数字、型号、年份，都能在 `调研/{选题}-调研资料.md` 里找到出处
- 找不到出处的，要么删，要么列进交稿回复的"拿不准"里
- 为了好懂做的简化，有没有简化成错的？（判断方法：懂行的人听了会不会在评论区纠错）
- 稿子里有没有保险话（"并没有公开确认""一种比较合理的推测是"）？有的话删掉，列进"拿不准"，稿子里直接讲

## 2. 前3秒留不留得住人

- 只看开头两三句：一个刷到这条视频的陌生人，有没有理由不划走？
- 开头的方式和最近两篇有没有重复？（翻一下 `稿件库/2-正式稿/`）

## 3. 顺不顺

- 每段读完，问一句"观众这时候会想问什么"，看下一段是不是在回答它
- 有没有哪段删掉之后，观众完全不会察觉？有就删
- 有没有观众听不懂的词没解释？
- 从头到尾大声读一遍，拗口的句子改短

## 4. 硬性规则扫描

在项目根目录运行，把 `{选题}` 换成文件名：

```bash
grep -nE "不是[^。！？]{0,40}而是|军备|战争|大战|战场|路径依赖|底层逻辑|多方博弈|用户心智|囚徒困境|三重结构|[0-9]{1,2}:[0-9]{2} *- *[0-9]{1,2}:[0-9]{2}" "稿件库/1-初稿/{选题}.md"
```

有输出就逐条改掉。然后人工再看一眼：
- 完整念出处（"根据XX机构XX年的数据"）是不是不超过2次
- 关键位置是否都有 `【画面：XXX】`

## 5. 时长

统计口播净字数（排除画面标注、标题、分隔线、引用行），按 330 字/分钟换算，和调研需求里定的时长对一下。超出 ±30 秒就调整篇幅。

```bash
sed -E '/^#/d; /^---/d; /^>/d; s/【画面[^】]*】//g' "稿件库/1-初稿/{选题}.md" | tr -d '[:space:]' | wc -m
```

---

检查结果不用单独汇报，有问题直接改；改不了的写进交稿回复。
