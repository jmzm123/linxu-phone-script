## 一、规则优先级

按以下顺序决定读法：

1. 用户在当前任务中明确指定的读音。
2. 本文件中的产品、协议和项目专用读法。
3. 同一项目既有 TTS 稿中已经稳定使用的读法。
4. 根据上下文确定的语义读法。
5. 本文件中的通用数字、单位和符号规则。

不得为了套用规则而改变产品名、事实、数字含义或量级。遇到未覆盖的新型号时，先依据同项目语境类推；只有两个候选读法差异明显且无法判断时才询问用户。

## 二、数字语义

转换前先识别数字属于哪一类。

| 类型 | 书面写法 | 口播读法 |
| --- | --- | --- |
| 普通数量 | `12 小时` | `十二小时` |
| 大数量 | `200,000 字` | `二十万字` |
| 年份 | `2026 年` | `二〇二六年` |
| 日期 | `2026 年 8 月 16 日` | `二〇二六年八月十六日` |
| 时间 | `8:30` | `八点三十分` |
| 小数 | `4.21` | `四点二一` |
| 百分比 | `10%` | `百分之十` |
| 范围 | `10–60 秒` | `十到六十秒` |
| 序数 | `第 3 代` | `第三代` |
| 公式 | `1+3+4` | `一加三加四` |
| 比例 | `16:9` | `十六比九` |
| 版本 | `2.5.0` | `二点五点零` |
| 温度负值 | `-5℃` | `零下五摄氏度` |
| 数学负值 | `-5` | `负五` |

- 年份逐位读，普通数量按数值读。
- 小于一的小数保留开头的零：`0.5` → `零点五`。
- 版本号、协议号和型号中有意义的零不得省略：`4.0` → `四点零`。
- 日期、时间、比例、版本和小数虽然可能使用相同符号，必须按上下文分别处理。
- 手机容量组合不是数学运算：`12+256GB` 可读作 `十二加二百五十六 G B 版本`，不得扩写成算术结果。
- 编号、代号和协议代码可以逐位读；不要把它们转换成普通数量。

## 三、产品型号

型号中的数字属于产品名，不得先套用普通数量规则。

### 联发科天玑（MediaTek Dimensity）

对于数字部分以两个零结尾的四位天玑型号，使用本项目简化读法：读出千位数值；百位非零时直接读百位数字，不读“百”和末尾两个零。产品名和型号之间有没有空格，不影响规则。

| 书面写法 | 口播读法 |
| --- | --- |
| `天玑 9500` | `天玑九千五` |
| `天玑9400` | `天玑九千四` |
| `天玑 9300` | `天玑九千三` |
| `天玑 9200` | `天玑九千二` |
| `天玑 8500` | `天玑八千五` |
| `天玑 8300` | `天玑八千三` |
| `天玑 8100` | `天玑八千一` |
| `天玑 1200` | `天玑一千二` |
| `天玑 1000` | `天玑一千` |
| `天玑 9000` | `天玑九千` |

后缀单独读，并统一字母大小写：

- `天玑 9500s` → `天玑九千五 S`
- `天玑 9400+` → `天玑九千四 Plus`
- `天玑 9300E` → `天玑九千三 E`

不得写成“天珑”，也不得读成“天玑九千五百”。这套简化读法不能用于价格、频率、电池容量、年份或其他型号系列。

### 高通骁龙（Qualcomm Snapdragon）

按惯用型号读法处理，不把型号当作普通基数词。

| 书面写法 | 口播读法 |
| --- | --- |
| `骁龙 888` | `骁龙八八八` |
| `骁龙 865` | `骁龙八六五` |
| `骁龙 810` | `骁龙八一零` |
| `骁龙 8 Gen 1` | `骁龙八 Gen 一` |
| `骁龙 8s Gen 3` | `骁龙八 S Gen 三` |
| `骁龙 8+ Gen 1` | `骁龙八加 Gen 一` |
| `骁龙 8 Elite Gen 5` | `骁龙八 Elite Gen 五` |

原文明确讨论档位系列时，依据上下文使用系列的惯用读法。例如 `骁龙 800 系列` 不必机械转换成逐位型号读法。

### Apple 及其他字母数字型号

在字母和数字之间建立读音边界，再按具体型号的惯用方式处理数字。

| 书面写法 | 口播读法 |
| --- | --- |
| `A19 Pro` | `A 十九 Pro` |
| `O1` | `O 一` |
| `iPhone 17 Pro Max` | `iPhone 十七 Pro Max` |
| `X65` | `X 六十五` |
| `IMX989` | `I M X 九八九` |

注意区分字母 `O`、`I` 与数字 `0`、`1`。不要自行翻译或改写品牌词。

| 书面写法 | 口播读法 |

| `120Hz` | `一百二十赫兹` |
| `40MHz` | `四十兆赫兹` |
| `600Mbps` | `六百兆比特每秒` |
| `40Gbps` | `四十吉比特每秒` |
| `50MB/s` | `每秒五十兆字节` |
| `120fps` | `每秒一百二十帧` |
| `8ms` | `八毫秒` |
| `5000mAh` | `五千毫安时` |
| `100W` | `一百瓦` |
| `3.7V` | `三点七伏` |
| `5A` | `五安` |
| `50mm` | `五十毫米` |

## 七、传感器尺寸

传感器尺寸中的 `1/1.49 英寸` 是分数形式。按分数规则先读分母，再读“分之”，最后读分子。

| 书面写法 | 口播读法 |
| --- | --- |
| `1/1.49英寸` | `一点四九分之一英寸` |
| `1/1.56英寸` | `一点五六分之一英寸` |
| `1/1.28英寸` | `一点二八分之一英寸` |
| `1/2.0英寸` | `二点零分之一英寸` |
| `1英寸` | `一英寸` |

不得读成“六分之一点四九英寸”“一分之一点四九英寸”“一英寸一点四九”或其他颠倒分子、分母的形式。

## 八、符号

- 数学语境中的 `+`、`×`、`=` 分别读作“加”“乘”“等于”。
- 手机容量配置中的 `+` 表示组合，不得计算求和。
- 产品后缀 `+` 按产品惯用名读作 `Plus` 或“加号版”。
- 范围连接号和表示区间的波浪号读作“到”；单独表示近似时读作“大约”。
- 负号根据语境读作“负”或“零下”；产品名中的连字符通常只建立读音边界。
- `/` 根据上下文读作“每”“比”“或”“斜杠”或分数，不得统一替换。
- 比例中的冒号读作“比”，时间中的冒号改成“点”或“时”。
- `<`、`>`、`≤`、`≥`、`±` 分别按语义展开为“小于”“大于”“小于等于”“大于等于”“正负”。
- `&` 读作“和”。
- 只有不影响语义时才删除装饰性引号、括号和分隔符。

## 九、停顿和段落

只使用 `<#x#>`，其中 `x` 为 `0.01` 到 `99.99` 秒，最多两位小数。

有效用法：

```text
这个正常。<#0.25#>还有一种情况。
```

```text
上一部分到这里。

<#1.5#>

接下来讨论新的问题。
```

- 标签必须位于两个可朗读文本段之间。
- 内联标签放在中文标点之后，不要插入词语内部。
- 独立标签可以单独成行，但前后都必须存在口播正文。
- 不得把标签放在全文开头或结尾，不得连续放置。
- `<#0#>`、`<#100#>`、`<#0.001#>`、`<##>` 和 `<#>` 都是非法标签。
- 根据真实语义转折选择时长，不要给所有句子或段落套用统一默认值。

## 十、最终检查

从头到尾完成以下检查：

1. 对照源稿内部转换清单，确认每个数字、型号、单位、协议和缩写都有且只有一个对应处理。
2. 确认没有事实删除、数字丢失、量级变化、型号串改或段落错序。
3. 确认没有标题、Markdown 语法、链接、资料备注、画面提示和作者备注。
4. 确认停顿标签之外没有阿拉伯数字。
5. 确认每个型号都使用所属产品系列的读法。
6. 确认每个小数和版本号保留所有有意义的数位。
7. 确认单位保持原始量级，并正确区分比特和字节。
8. 确认紧凑技术缩写已按需要拆分。
9. 确认每个停顿对应真实转折，且前后都有可朗读正文。

## 完整示例

书面原稿：

```text
天玑9500采用1+3+4的八核设计，最高频率为4.21GHz，并使用3nm工艺。官方称CPU性能提升10%。
```

TTS 纯口播稿：

```text
天玑九千五采用一加三加四的八核设计，最高频率为四点二一吉赫兹，并使用三纳米工艺。官方称 C P U 性能提升百分之十。
```
