# 校准 ASR 生成的 SRT 字幕

以口播定稿为准，修正语音识别生成的 SRT 字幕文本。

## 输入

- 口播定稿：通常是 `稿件库/正式稿件/` 下的正式稿件，或其对应的 `（TTS纯口播稿）.md`。两者内容一致，只是数字写法不同；优先参照正式稿件，因为只有它保留了书面数字形态。
- ASR 生成的 `.srt` 文件。文本由语音转文字产生，可能包含错别字、错误断词、乱码数字和专有名词误识。

## 校准标准

1. **时间轴和结构绝对不动**。字幕条数、每条序号、起止时间戳与原 SRT 完全一致；只修改文本行。不合并、不拆分、不调轴。
2. **文本以定稿为准**。按时间顺序和语义把每条字幕对应到定稿句子，修正 ASR 的错别字、错词、乱码和断句错误。一条字幕通常对应定稿句子的一个片段。
3. **全文无标点**。删除所有中英文标点（，。！？；：、——……“”"" 等）。带语义的符号转成文字：`×` → 乘、`%` → 百分之、`+` → 加、`vs` → 对。唯一例外是数字内部的小数点（如 `16.3毫米`、`2.4倍`）。删除标点后不留多余空格。
4. **数字和型号用书面风格**。口播稿里的读音形式要还原成书面写法：`零八零九` → `0809`、`二〇一九年` → `2019年`、`九十赫兹` → `90Hz`、`iPhone 六 S` → `iPhone 6s`、`一加七 Pro` → `一加7 Pro`。百分比写作 `百分之90` 这种形式。ASR 乱码数字（如 `080 9081 50916`）按定稿还原（`0809 0815 0916`）。
5. **专有名词和术语按定稿与项目约定**。包括品牌大小写（`OPPO`、`vivo`、`iPhone`、`iOS`、`APP`、`Taptic Engine`、`mEngine`）、型号（`真我GT7 Pro`）和物理术语（`洛伦兹力`、`质量块`）。本项目账号名是“林序”，ASR 常误识为“林旭”。本项目统一使用“振动马达”“振动”，不用“震动”。
6. **不得发明内容**。定稿之外的话（临场发挥、脱稿内容）以语义最接近的定稿句子修正；若某条完全无法对应，保留最接近的合理修正并在报告中说明，不要编造。

## 输出

- 在原 SRT 同目录创建 `原文件名-校准.srt`，不覆盖原文件；用户明确要求覆盖时除外。
- 正文只含序号、时间轴和校准后的字幕文本，保持 UTF-8 编码和原文件的换行风格。

## 自检（必须执行）

1. 运行 `python3 scripts/srt_check.py <原始.srt> <校准后.srt>`，确认序号与时间轴一致、无标点、无空白异常。修复每个警告后才算完成。
2. 抽查开头、中间、结尾各若干条，对照定稿确认文本对应正确。
3. 全文搜索常见风险点：残留的“震动”、误识人名（林旭等）、中文数字读音形式（如 `赫兹`、`二〇` 开头）、乱码数字。

## 报告

向用户说明：字幕条数、修改条数、主要修正类型（举例）、无法确定对应关系的字幕（如果有）、输出文件路径。
