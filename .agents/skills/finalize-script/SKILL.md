# 定稿

林序在 `稿件库/1-初稿/` 里改完稿子后，一次做完定稿的全部步骤。

**最重要的一条：以林序改过的文件为准。** 任何时候都不得用自己手里的旧版本覆盖他的修改，也不得擅自改他的文字；发现问题只能提出来，由他决定。

## 输入

- `稿件库/1-初稿/{选题}.md`：林序改过的版本
- `稿件库/0-AI原稿/{选题}.md`：Claude 写的原样备份（可能没有，老稿子就没有）

选题不明确时，列出 `1-初稿/` 里的文件让林序选。

## 流程

### 1. 读取和对比

在项目根目录运行：

```bash
python3 .agents/skills/finalize-script/scripts/finalize_check.py "{选题}"
```

脚本会：
- 检查初稿是否存在，正式稿是否已有同名文件
- 输出 AI 原稿和林序版本的逐行差异（没有备份时跳过）
- 扫描禁用句式和禁用词
- 统计口播净字数，按 330 字/分钟估算时长

然后**完整读一遍林序改过的初稿**。脚本只看得到差异，看不到断口。

### 2. 找断口（必须做）

林序删改之后，前后文可能接不上了。重点查：

- **没有下文的铺垫**：他删了一节，前文却还留着"我们马上说到""后面会讲""最后说个……"这种话
- **悬空的指代**：删掉的内容在别处被"这个""刚才说的""那个数字"指着
- **列举对不上**：说了"三件事"，实际只剩两件；或者他删了"第一件"之类的编号，后面还有"第三件"
- **总结和正文不符**：结尾总结里提到的点，正文已经删了
- **画面标注孤立**：`【画面：XXX】` 描述的内容，对应的口播已经删了
- **格式残留**：连续的 `---`、多余空行、只剩标题没有正文的章节

发现断口时，**先不移动文件**。把问题连同所在行号、原文一起告诉林序，给一两个最小改法（优先"删掉那句"），等他选。他选定后只改那一处。

没有断口就直接往下走。

### 3. 移入正式稿

1. 修完断口后，**重新读取**初稿当前内容
2. 用 `mv` 移动到 `稿件库/2-正式稿/{选题}.md`，文件名不变。不要用"读出来再写进去"的方式，避免把内容改掉
3. 正式稿保留 `【画面：XXX】`、章节标题等制作信息

`2-正式稿/` 已有同名文件时，先停下来问林序是覆盖还是另存。

### 4. 导出口播稿

调用项目技能 **prepare-minimax-tts**，把正式稿转成 `稿件库/3-口播稿/{选题}（TTS纯口播稿）.md`，按那个技能的全部规则执行，包括读完它的发音规则和跑 lint。

### 5. 记录修改规律

对比 `0-AI原稿/` 和正式稿，把林序的修改归纳成规律，追加到 `文档/林序修改记录.md`：

- 在「目前总结出的规律」末尾续编号，每条写成**一句加粗的做法**，后面跟这次的原文例子（改前→改后）
- 在「逐篇记录」下新增这一篇：得出了哪几条、有没有特殊情况
- **只记能指导下次写稿的规律**。错别字、个别措辞这种一次性修改不记
- 和已有规律重复的，不新增条目，在原条目后补上这次的例子
- 和已有规律冲突的，如实写出冲突，标"待更多稿子验证"，不要硬凑成新规律
- 看不出为什么改的，问林序一句，不要替他编理由
- 定稿时修掉的断口也要记，写成给 Claude 自己的提醒

没有 AI 原稿时跳过这一步，在报告里说明。

## 报告

回复林序，要短：

- 正式稿、口播稿的路径
- lint 结果；口播稿里值得他试听确认的读法（比如不常见的单位、型号）
- 这次总结出的修改规律（一句话一条）
- 如果有，定稿时修掉的断口
- 是否已提交 git（默认不提交，除非林序要求）
